3. FILE FORMAT
------------------------------------------------------------------------------

  Plain UTF-8 text. Documents are separated by a line containing exactly:

      <|endoftext|>

  So the file looks like:

      <document 1, paragraphs separated by one empty line>

      <|endoftext|>

      <document 2 ...>

  Paragraph structure inside a document is preserved (one empty line between
  paragraphs). If you prefer another convention, replace the separator, e.g.

      sed 's/^<|endoftext|>$/=====/' train.txt > train_alt.txt

  or simply split on the marker:

      python3 -c "import sys;print(len(open('train.txt').read().split('\n\n<|endoftext|>\n\n')))"

5. HOW THE DATA WAS CLEANED
------------------------------------------------------------------------------

  1. Extraction      : 925,316 raw documents
                       (736,630,689 characters) unpacked from the upstream formats
                       (CSV, TSV, JSONL, tab-separated chat logs, text trees).
  2. Normalization   : Unicode NFKC, Arabic presentation forms folded to base
                       letters, Arabic ي/ك/ة -> Persian ی/ک/ه, Arabic-Indic and
                       Latin digits -> Persian digits, diacritics removed,
                       tatweel/ZWNJ-corrupting characters removed, ZWNJ kept,
                       whitespace and punctuation spacing repaired, empty brackets
                       and doubled punctuation repaired, HTML tags, entities,
                       URLs, e-mails, wiki templates/links/refs removed.
                       Back-to-back duplicated words and short phrases (a
                       wiki-link flattening artefact, e.g. 'فیلم ترسناک ترسناک')
                       are collapsed for prose sources.
                       Every character outside the Persian alphabet, Persian
                       digits, Persian punctuation, space/newline and ZWNJ is
                       dropped, so Latin-script words and emoji do not survive.
  3. Line cleaning   : navigation/boilerplate lines (share buttons, 'کد خبر',
                       'کلیه حقوق محفوظ', social links, page numbers) dropped;
                       lines with fewer than 3 Persian letters dropped.
  4. Quality gate    : per-source minimum length, Persian-letter ratio >= 80%,
                       Latin-letter and digit-ratio caps, sentence-length and
                       fragment checks, repeated-line and repeated-4-gram checks,
                       compression-ratio check for numeric/table garbage.
                       -> 274,860 documents kept
                          (538,849,962 characters)
  5. Deduplication   : 317 exact duplicates + 4,521 near-duplicates removed
                       (SHA-1 of the normalized text; one-permutation MinHash
                       over 4-word shingles, 4-band LSH, >=12/16 buckets equal)
                       -> 270,022 unique documents
  6. Budget balance  : per-source caps keep the mix comparable to real-world
                       Persian text. Wikipedia is sampled per article-length
                       band (short/medium/long/very long) and ranked by a
                       quality score inside each band, so the sample keeps
                       encyclopedic breadth instead of collapsing onto a few
                       thousand very long articles.
                       -> 36,592 documents shipped
  7. Verification    : independent re-scan of the written files (see section 8).

7. KNOWN LIMITATIONS - READ BEFORE TRAINING
------------------------------------------------------------------------------

  * Size. The corpus is deliberately capped (see section 9) to stay inside the
    repository budget. For a 100M-parameter model this is a small corpus:
    11,350,801 tokens is well below the ~2B tokens that
    Chinchilla-style scaling would suggest. Expect to repeat epochs, and
    expect validation loss to bottom out early; treat it as a starting
    corpus and extend it as more Persian text becomes available.
  * Register skew. Encyclopedic text is 78% of the corpus and
    journalistic text is another ~10%, so encyclopedic/journalistic registers
    dominate; dialogue is only a few percent and is informal/colloquial
    (Tehran chat), so the model will not be equally fluent in every register.
  * Poetry. 5.0% of the corpus is classical verse (Rumi, Hafez, Saadi, ...).
    It is stylistically very different from modern prose; if you want a purely
    modern-prose model, rebuild without ganjoor_classics/persian_poetry.
  * Date. The Wikipedia dump is dated 2021-02-01 and the news sources are from
    roughly 2015-2019, so the model will not know anything later than that.
  * Format artefacts. Dialogue and QA sources were re-formatted into readable
    documents ('کاربر: ...', 'پرسش: ...', 'متن نخست: ...'). These markers are
    part of the text; the model will learn to produce them in dialogue-like
    contexts. They are a few percent of the corpus.
  * Informal content. The chat source may contain slang, opinions, politics and
    occasional profanity; it was not semantically filtered. For a model that
    must be safe to deploy, filter or drop peqa_dialogue.
  * Residual link-flattening artefacts. The Wikipedia dump expands piped wiki
    links by keeping both the target and the label, which occasionally leaves a
    near-duplicate ('ترکیه ترکیه‌ای', 'دی سی کامیکس دی‌سی کامیکس'). Immediate
    word/phrase repeats are removed, but variants that differ in spelling or
    ZWNJ cannot be detected safely and survive in a small share of documents.
  * No OCR/PDF text, no books published after ~1930 (copyright), no social media
    beyond the chat corpus.
  * Normalization choice. Digits are Persian, diacritics are removed, ZWNJ is
    kept. If your downstream task needs Latin digits, transliterate them.

9. WHY THE CORPUS IS CAPPED, AND HOW TO GET MORE
------------------------------------------------------------------------------

  The cleaning stage produced 538,849,962
  characters of acceptable Persian text, but this repository is limited to a
  practical Git artefact size, so the shipped files hold a documented sample
  of 44,999,973 characters. The sampling is deterministic and
  quality-weighted, and the full cleaned corpus can be regenerated with one
  command (larger --budget):

      python3 pipeline/build_dataset.py --extracted <work>/extracted \
          --tmpdir <work>/build --outdir ./full --budget 450000000

  Nothing is thrown away permanently: the pipeline is reproducible end to end
  from pipeline/fetch_sources.sh.

10. HOW TO REPRODUCE / REBUILD
------------------------------------------------------------------------------

      # 1. download the sources (~2 GB, public GitHub repositories only)
      WORKDIR=/tmp/work bash pipeline/fetch_sources.sh

      # 2. unpack upstream formats into a uniform document stream
      python3 pipeline/extract_sources.py --workdir /tmp/work \
          --out /tmp/work/extracted

      # 3. clean, filter, deduplicate, balance, split
      python3 pipeline/build_dataset.py --extracted /tmp/work/extracted \
          --tmpdir /tmp/work/build --outdir . --budget 45000000

      # 4. statistics and token counts
      python3 pipeline/compute_statistics.py --manifest /tmp/work/build/selected_manifest.tsv \
          --build-report /tmp/work/build/build_report.json \
          --token-stats tokenizer/token_stats.json --out dataset_statistics.json
      python3 pipeline/make_tokenizer.py --out-dir tokenizer

      # 5. verification
      python3 pipeline/verify_dataset.py

  Requirements: Python 3.9+, standard library only, except tokenizers
  (pip install tokenizers) for step 4 and py7zr for unpacking the Wikipedia
  archive. Runtime is ~30 minutes on 2 CPU cores.
